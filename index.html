🏴‍☠️ Treasure Hunt Game — Key Takeaways

A full-stack React + Express project built with Claude Code, covering game logic, auth, database, animations, and deployment.

📋 Project Overview ▼

🎮

Game Concept

Pick 2 of 3 treasure chests. One chest hides treasure (+$100), the others contain skeletons (-$50). Game ends when treasure is found or 2 chests are opened. Final score determines Win / Tie / Loss.

🔐

Auth & Persistence

Authenticated users get scores saved to SQLite via JWT. Guest mode lets anyone play without sign-up — no server interaction needed.

🧩

Tech Stack

React 18 Vite + SWC Tailwind CSS Framer Motion shadcn/ui Express 5 better-sqlite3 bcryptjs JWT

Client — src/

  • AuthPage.tsx — sign-in / sign-up forms
  • ScoreHistory.tsx — past scores table (last 20)
  • GameEndAnimation.tsx — particle effects on game end
  • components/ui/ — shadcn/ui (Radix UI) library

Server — server/index.js

  • POST /api/signup — create user (bcrypt hash)
  • POST /api/signin — login, return JWT (24h)
  • POST /api/scores — save game score (auth)
  • GET /api/scores — fetch user's last 20 scores
  • Production: serves built frontend from build/

✨ Key Features Implemented ▼

🎲

Random Treasure Placement

One of 3 chests is randomly assigned treasure each game via Math.floor(Math.random() * 3).

🔊

Sound Effects

chest_open.mp3 plays for treasure. chest_open_with_evil_laugh.mp3 plays for skeletons. Triggered on box click.

🎭

Animations

Framer Motion powers chest flip (rotateY), hover scale, score pop-in, result badge entrance, and particle effects on game end.

🔑

Custom Cursor

key.png used as a CSS custom cursor when hovering over closed chests — a fun UX detail.

🏆

Win / Tie / Loss Display

Final score determines outcome: >0 = Win (green), 0 = Tie (amber), <0 = Loss (red). Animated badge with color-coded styling.

📊

Score History

Authenticated users see their last 20 game results fetched from SQLite. Auto-refreshes after each game.

🤖 Claude Code Workflow Learned ▼

  1. /init — Generate CLAUDE.md so Claude understands the project structure, commands, and architecture.
  2. @ File References — Use @src/audios/chest_open.mp3 to point Claude to specific assets. Keeps prompts precise and context-aware.
  3. # Project Memory — Save rules (e.g., "always add function comments") with # so Claude follows them in future turns.
  4. Screenshot-driven dev — Paste a screenshot, circle an area, describe the change. Claude implements visually.
  5. /context & /compact — Monitor token usage (/context), compress history (/compact), or reset (/clear) to manage context window.
  6. Plan Mode (Shift+Tab) — Think before coding. Explore options like database choices (SQLite vs. others) before committing to implementation.
  7. Ultrathink — Prefix with "Ultrathink" for deeper reasoning on complex features (e.g., full sign-up/sign-in + score persistence).
  8. Custom Commands — Create .claude/commands/deploy_vercel.md or deploy_github_page.md for reusable deployment workflows.
  9. Ctrl+T — To-Do List — Track Claude's task progress in real-time during multi-step implementations.
  10. Esc+Esc — Conversation Picker — Jump between conversations to manage different feature branches or tasks.

💡 Claude Code Tips & Tricks ▼

📌

Be Specific, Then Stop

"Use @file in @component to do X. Do not do anything else." — constraining scope prevents Claude from over-engineering.

🔄

Verify After Each Step

"Check the comments of existing changes" — always review Claude's work before moving on. Catch drift early.

💾

Commit Before Experimenting

Make a git commit before Plan Mode or Ultrathink. Easy rollback with git revert if things go sideways.

🧠

Context is King

Monitor with /context. 27% used? Fine. Getting high? /compact to compress. Starting fresh? /clear.

🎯 Top Takeaways ▼

  • Full-stack in one session — React game + Express API + SQLite auth, built iteratively with Claude Code.
